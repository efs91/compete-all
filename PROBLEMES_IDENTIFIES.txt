🔴 PROBLÈMES CRITIQUES - BLOQUANTS
================================================================================

1. ERREUR CRITIQUE - Modèle manquant : PointsClassement
   -----------------------------------------------------------------------
   Localisation: app/routers/classements.py (lignes 56, 98, 105)
   
   Le code référence models.PointsClassement qui N'EXISTE PAS dans models.py
   Le modèle Classement a une colonne points de type JSON, mais le routeur 
   classements essaie d'utiliser un modèle relationnel qui n'existe pas.
   
   Exemple d'erreur:
   ```python
   db_point = models.PointsClassement(...)  # Cette classe n'existe pas !
   ```
   
   Conséquence: Crash immédiat au chargement des routes classements.
   
   Solution: Créer le modèle PointsClassement OU refactoriser le routeur
            pour utiliser le JSON directement.


2. Incohérence Architecture Classements
   -----------------------------------------------------------------------
   Le modèle Classement stocke les points en JSON:
   ```python
   points = Column(JSON, nullable=False)  # {joueur_id: points, ...}
   ```
   
   Mais le routeur essaie de créer des entrées relationnelles séparées 
   avec PointsClassement.
   
   Il faut choisir une architecture:
   - Option A: JSON simple (plus rapide, moins flexible)
   - Option B: Table relationnelle (plus structuré, requêtes complexes)


3. Relation equipe.membres cassée
   -----------------------------------------------------------------------
   Localisation: app/routers/equipes.py (lignes 18, 53)
   
   Le code essaie d'assigner une liste d'objets Joueur:
   ```python
   db_equipe.membres = [db.query(models.Joueur)...]  # ERREUR
   ```
   
   Mais dans schemas.py, EquipeBase.membres est défini comme List[str] 
   (liste d'IDs), pas d'objets Joueur. Il y a confusion entre le schéma 
   Pydantic et la relation SQLAlchemy.
   
   Le modèle utilise la relation equipe_joueur (many-to-many), mais le 
   routeur n'utilise pas correctement cette relation.
   
   Solution: Utiliser db_equipe.joueurs.append(joueur) ou gérer 
            manuellement avec equipe_joueur.insert()


4. Mauvaise gestion des relations Equipe
   -----------------------------------------------------------------------
   Le modèle SQLAlchemy dit:
   ```python
   equipes = relationship("Equipe", secondary=equipe_joueur, 
                         back_populates="joueurs")
   ```
   
   Mais le schéma Pydantic attend une liste d'IDs de strings.
   
   Incohérence entre:
   - Modèle DB: utilise relationship() pour many-to-many
   - Routeur: assigne directement .membres (qui n'existe pas en DB)
   - Schéma: attend List[str] d'IDs


5. Architecture de Rencontre incomplète

Structure des relations complexes identifiées:
----------------------------------------------

1. Table ternaire phase_evenement_joueur:
   - Lie: Phase + Evenement + Joueur
   - Colonnes: phase_id, evenement_id, joueur_id, ordre_inscription, seed
   - But: Un joueur peut participer à différentes phases dans différents 
          événements avec des seeds différents

2. Table many-to-many phase_evenement:
   - Lie: Phase + Evenement
   - But: Une phase (template) peut être réutilisée dans plusieurs 
          événements

3. Table many-to-many equipe_joueur:
   - Lie: Equipe + Joueur
   - But: Un joueur peut être dans plusieurs équipes
   - PROBLÈME: Mal utilisée dans le code actuel
